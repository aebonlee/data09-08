### 정한 것과 이유

- **글자 대신 위치로 칸을 나눕니다.** 이어 붙인 글자에 정규식을 걸면 공차 칸이 빈 줄에서 편차가 상한공차 자리로 밀립니다. 숫자가 오른쪽 정렬이라 오른쪽 끝 x 는 줄마다 같습니다(실제 5건 모두 272 / 323 / 374 / 425 / 473 / 564pt).

- **항목명 오기는 조용히 고치지 않습니다.** 적힌 한계값으로 판정하고 확인필요로 띄웁니다.
- **끼워맞춤 표 값은 「확인」 표시와 함께만.** 받은 자료의 g6·f6 이 표 값과 같았지만, 사내 규격을 따로 쓰는지 모릅니다.

- **번호 없는 도면** — 「번호 풍선 새로 찍기(자동 번호)」: 도면을 누를 때마다 다음 번호 풍선 + 기준표 항목, 옆에서 기준값·공차 입력. 「번호 없는 측정 짝 맞추기」: 기준값·공차로 도면 항목을 제안(`suggestMatches`), 확인한 줄만 반영(`applyMatches`, 원래 번호는 `orig_no`). 「기준값으로 기준표 항목 만들기(자동 번호)」(`specFromMeas`).
- **과제 B 사진 등록** — 협력사·설비·점검일 + 점검표 사진 → 점검항목별 판정·측정값 입력 → 등록. 사진 지문(`hashBytes`)으로 같은 사진 재업로드 경고 + 규칙 검사 「같은 사진 — 확인 필요」.
- **AI 읽기(선택)** — 폐쇄망 모드를 끈 때만 보입니다. 사용자 OpenAI 키(브라우저에만 저장, 백업에 없음)로 비전 모델 호출 → JSON → 입력표에 채움(파란 칸, 불확실은 노란 칸) → 사람이 확인해 등록. 키 없는 반자동(요청문 복사·답 붙여넣기)도 둠. 요청문에는 항목번호·항목명만 넣고 기준값·공차는 넣지 않습니다.
- 예시 파일 2개 추가(가상): `samples/예시데이터_CMM결과_번호없음.csv`, `samples/예시데이터_CMM_PDF복사본.txt`(장비 번호 P1…).
- `supabase/schema.sql`: measurement 번호 빈칸 허용 + nominal·tol_upper·tol_lower·orig_no·matched·photo, daily_check.photo_hash, app_settings.offline_mode·ai_model. 이미 만든 표에도 맞춰지도록 `add column if not exists` 블록. 로컬 PostgreSQL 하네스 통과(두 번 적용 포함).
- 고친 결함: ① 도면 핀이 `ellipse` 인데 CSS 가 `circle` 만 칠해 판정 색이 안 나오던 것 ② 열 지정 「가져오기」 뒤의 「바꾸기/덧붙이기」 대화상자가 같은 닫기에 함께 닫혀, 이미 측정값이 있을 때 파일 가져오기가 조용히 무시되던 것(한 박자 뒤에 넘기도록).

### 정한 것과 이유
