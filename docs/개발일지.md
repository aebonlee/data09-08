- **수기 측정표 사진 등록** — `capture=environment` 촬영, 확대(최대 800%)·회전 보기 + 기준표 항목별 측정값 입력표. 사진은 저장하지 않고 측정값에 파일 이름만 남깁니다.
- **번호 없는 도면** — 「번호 풍선 새로 찍기(자동 번호)」: 도면을 누를 때마다 다음 번호 풍선 + 기준표 항목, 옆에서 기준값·공차 입력. 「번호 없는 측정 짝 맞추기」: 기준값·공차로 도면 항목을 제안(`suggestMatches`), 확인한 줄만 반영(`applyMatches`, 원래 번호는 `orig_no`). 「기준값으로 기준표 항목 만들기(자동 번호)」(`specFromMeas`).
- **과제 B 사진 등록** — 협력사·설비·점검일 + 점검표 사진 → 점검항목별 판정·측정값 입력 → 등록. 사진 지문(`hashBytes`)으로 같은 사진 재업로드 경고 + 규칙 검사 「같은 사진 — 확인 필요」.
- **AI 읽기(선택)** — 폐쇄망 모드를 끈 때만 보입니다. 사용자 OpenAI 키(브라우저에만 저장, 백업에 없음)로 비전 모델 호출 → JSON → 입력표에 채움(파란 칸, 불확실은 노란 칸) → 사람이 확인해 등록. 키 없는 반자동(요청문 복사·답 붙여넣기)도 둠. 요청문에는 항목번호·항목명만 넣고 기준값·공차는 넣지 않습니다.
- 예시 파일 2개 추가(가상): `samples/예시데이터_CMM결과_번호없음.csv`, `samples/예시데이터_CMM_PDF복사본.txt`(장비 번호 P1…).
- `supabase/schema.sql`: measurement 번호 빈칸 허용 + nominal·tol_upper·tol_lower·orig_no·matched·photo, daily_check.photo_hash, app_settings.offline_mode·ai_model. 이미 만든 표에도 맞춰지도록 `add column if not exists` 블록. 로컬 PostgreSQL 하네스 통과(두 번 적용 포함).
- 고친 결함: ① 도면 핀이 `ellipse` 인데 CSS 가 `circle` 만 칠해 판정 색이 안 나오던 것 ② 열 지정 「가져오기」 뒤의 「바꾸기/덧붙이기」 대화상자가 같은 닫기에 함께 닫혀, 이미 측정값이 있을 때 파일 가져오기가 조용히 무시되던 것(한 박자 뒤에 넘기도록).

### 정한 것과 이유

- **폐쇄망에서 사진 자동 인식은 하지 않았습니다.** 브라우저에 OCR 이 내장돼 있지 않고, tesseract.js 는 언어 데이터 포함 수십 MB 라 도구 폴더에 넣기 무겁고 손글씨 인식률도 미검증입니다. 대신 사진 옆 입력표 + 확대·회전으로 옮겨 적기를 빠르게 했습니다.
- **짝 제안은 제안만 합니다.** 판정은 계산 로직이 하되, 어느 측정이 어느 도면 항목인지는 사람이 확인해 반영합니다(1단계 원칙 「불확실한 항목을 강제 판정하지 않음」). 신뢰도 높음·보통만 기본 선택, 낮음(기준값 없이 값 범위로만 찾은 것)은 선택 해제 상태.
- **같은 기준 항목이 여럿이면 측정 순서대로 짝짓습니다.** CMM 은 보통 도면 순서대로 측정하므로 합리적인 기본값이지만 틀릴 수 있어 신뢰도를 「보통」으로 낮춰 표시합니다.
- **폐쇄망 모드 스위치는 전역 하나.** 과제 A(사내 PC, 켬)와 과제 B(협력사, 끔)는 서로 다른 PC·브라우저에서 쓰는 것을 전제로 했습니다.

### 정한 것과 이유

- **판정은 계산으로만 합니다.** 제출 문서가 "최종 OK/NOK 는 결정론적 계산 로직"으로 정했습니다. AI 는 1단계에 넣지 않았습니다(OCR 은 2단계).
- **모호하면 판정하지 않습니다.** 매칭 실패·값 누락·단위 불일치·공차 없음·항목번호 중복·같은 항목에서 CMM 과 수기 판정이 엇갈림 → 「확인필요」. 제출 문서의 "불확실한 항목을 강제 판정하지 않음" 원칙입니다.
- **열 지정 방식.** 실제 CMM 파일 구조를 모르므로 열 이름을 고정하지 않았습니다. 머리글 글자로 추정만 하고 사람이 확인합니다. CMM 출력 앞에 제목 줄이 있는 경우를 생각해 머리행 번호도 고릅니다.
- **부동소수 오차 정리.** 10 + 0.1 이 10.100000000000001 이 되어 경계값 10.1 이 NOK 로 나오는 것을 막으려고 상·하한과 편차를 소수 10자리에서 정리합니다.
- **도면은 긴 변 2400px 로 줄여 저장합니다.** localStorage 용량 때문입니다. 핀은 비율 좌표라 원본 해상도와 상관없습니다. 그래도 넘치면 메모리에만 두고 안내 띠를 띄웁니다.
- **임시 기준은 설정으로 뺐습니다.** 판정 전 반올림(기본 끔), 빈 단위 처리(기본 기준표 단위), 이름 매칭(기본 켬), 반복값 N(기본 비움 = 검사 안 함, 예시 데이터에서만 5).

### 가정 (수강생 확인 필요)

- (가정) 상·하한 경계값은 OK 입니다.
- (가정) 공차는 기준값에 더하는 값입니다(상한공차 +, 하한공차 −). 부호 없는 숫자 하나(「0.1」)는 ±인지 단측인지 알 수 없어 읽지 않고 확인필요로 둡니다.
- (가정) 콤마 하나만 있고 점이 없는 값(「12,5」)은 소수점 콤마로 읽습니다(중국·유럽 장비 출력 대비).
- (가정) CMM 측정번호와 도면 풍선 번호가 같은 체계입니다. 앞자리 0·「#」·전각 문자는 같게 봅니다(007 = 7 = #7).
- (가정) 과제 B 의 판정 칸에 ×·X·NG·불량·이상·NOK 가 적히면 이상 기입입니다.
